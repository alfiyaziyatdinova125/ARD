Типичные ошибки

Эти ошибки встречаются именно в адаптивном и отзывчивом дизайне — а не в вёрстке вообще. Ниже — разбор самых частых грабель и того, как их избежать.

Что мы узнаем

  • Горизонтальная прокрутка
  • Мелкий текст и кнопки
  • Игнорирование prefers-reduced-motion
  • Десктопные изображения на телефоне
  • «Мёртвые зоны» между брейкпоинтами
  • Фиксированные размеры в пикселях

1. Горизонтальная прокрутка на мобильных

Прямая проблема адаптивности: интерфейс не подстроился под ширину экрана, и контент «вылезает» за край. Пользователь вынужден скроллить вбок.

Причины:

  • Фиксированная ширина элемента больше ширины экрана
  • Отрицательные отступы
  • Изображения без max-width: 100%
  • Длинные слова или URL без переноса

Как исправить:

img {
    max-width: 100%;
    height: auto;
}

body {
    overflow-x: hidden;
}

.long-word {
    word-break: break-word;
}

2. Слишком мелкий текст и кнопки

Ошибка мобильной адаптации: интерфейс технически подстроился под экран, но остался неудобным. Мелкий шрифт и кнопки меньше 44×44 px делают сайт практически непригодным на телефоне.

Рекомендации:

  • Минимальный размер шрифта основного текста — 16px
  • Размер кнопок — не меньше 44×44 px
  • Расстояние между кликабельными элементами — минимум 8 px
button {
    min-height: 44px;
    min-width: 44px;
    font-size: 1rem;
}

3. Игнорирование prefers-reduced-motion

Ошибка отзывчивости: интерфейс не реагирует на предпочтения пользователя. Многие страдают от головокружения при виде анимаций, и в системе есть настройка «уменьшить движение».

Как исправить:

@media (prefers-reduced-motion: reduce) {
    * {
        animation: none !important;
        transition: none !important;
        scroll-behavior: auto !important;
    }
}

Это простой способ сделать адаптивность не только под экран, но и под состояние пользователя.

4. Загрузка десктопных изображений на телефон

Ошибка адаптации ресурсов: на мобильном грузится картинка, рассчитанная на большой монитор. Лишние мегабайты трафика и медленная загрузка.

Как исправить — использовать srcset и sizes:

<img src="img/photo-960.jpg"
     srcset="img/photo-480.jpg 480w,
             img/photo-960.jpg 960w,
             img/photo-1440.jpg 1440w"
     sizes="(max-width: 768px) 100vw,
            (max-width: 1200px) 70vw,
            800px"
     alt="Описание">

Браузер сам выберет подходящий размер изображения в зависимости от ширины экрана и плотности пикселей.

5. «Мёртвые зоны» между брейкпоинтами

Классическая проблема именно адаптивного подхода: макет предусмотрен для 320 px и для 768 px, но что происходит на 600 px — не продумано. В итоге на промежуточных разрешениях интерфейс выглядит сломанным.

Как избежать:

  • Использовать fluid-вёрстку внутри брейкпоинтов
  • Применять clamp() для шрифтов и отступов
  • Проверять макет на промежуточных разрешениях, а не только на «стандартных»
  • Использовать Container Queries вместо глобальных медиа-запросов

По сути, «мёртвые зоны» — это аргумент в пользу отзывчивого подхода: он не оставляет таких провалов, потому что макет плавно тянется.

6. Фиксированные размеры в пикселях

Причина неадаптивности как таковой. Когда ширина, отступы и шрифты заданы только в пикселях, макет «ломается» при малейшем изменении экрана или пользовательских настроек.

Плохо:

.container {
    width: 960px;
    padding: 40px;
    font-size: 18px;
}

Хорошо:

.container {
    max-width: 60rem;
    padding: clamp(1rem, 3vw, 2.5rem);
    font-size: clamp(1rem, 0.5rem + 1vw, 1.25rem);
}

Смешивание rem, %, vw и clamp() делает вёрстку гибкой и уважает пользовательские настройки размера шрифта. Это признак отзывчивого подхода.
